**GDB SaaS**
- Category: Binary Exploitation
- Rating: Easy
- Flag: `FortID{N0_5h3ll_n33d3D_jU57_m41N_fe059f12a9}`

Server yêu cầu người dùng gửi một ELF dưới dạng Base64, độ dài tối đa được cho phép của chuỗi này là 30270 kí tự.
![Screenshot 0](/assets/images/ctf/fortid-ctf-2026/gdb-saas/01.png)

Sau đó dữ liệu được ghi thành file ELF `a.out`, ngoài ra server cũng copy `flag.txt` vào thư mục `tmp_dir này`. Cuối cùng, server dùng **GDB** để `disassemble function` do người dùng chỉ định.
![Screenshot 1](/assets/images/ctf/fortid-ctf-2026/gdb-saas/02.png)

Ý tưởng chính của bài này là lợi dụng gdb để cố đọc nội dung của file `flag.txt` thật trên server. Ban đầu mục đích của server cho ta sẽ là `disassemble` một hàm bình thường, nhưng nếu như ta truyền `/s main` thì nó sẽ vừa in assembly và `source code` tương ứng.
Trên máy local, ta sẽ tạo 1 file `flag.txt` với nội dung là một file `.c` có hàm `main` thông thường. Khi ta compile bằng lệnh `gcc -x c -g1 -O0 -o payload flag.txt`
![Screenshot 2](/assets/images/ctf/fortid-ctf-2026/gdb-saas/03.png)

Kiểm tra trên local thấy exploit khai thác thành công, base64 file Elf vừa được compile rồi gửi cho server instance, sau khi có thông báo nhập `function name` thì nhập `/s main`.
ELF lưu debug information rằng code của hàm main đến từ file source tên flag.txt. Mà khi Server chạy thì nó lưu cả file `a.out` và `flag.txt` trong cùng 1 thư mục, lúc này `gdb /s main` sẽ in ra nội dung flag kèm mã assembly. Thực hiện tự động bằng script `pwn2.py`, ta thu được flag `FortID{N0_5h3ll_n33d3D_jU57_m41N_fe059f12a9}`.
