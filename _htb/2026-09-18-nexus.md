> This write-up documents work completed in an authorized lab environment. Flags and recovered passwords are intentionally omitted.

## Overview

Nexus is a Linux machine built around several connected weaknesses: exposed virtual hosts, credentials leaked through a Gitea repository, an unsafe file-upload flow in Krayin CRM, reused database credentials, and a privileged Gitea template synchronization service that trusts attacker-controlled paths.

The attack path is:

1. Enumerate the exposed services and virtual hosts.
2. Recover application credentials from Gitea history.
3. Abuse the CRM attachment upload to obtain a `www-data` shell.
4. Recover another credential from the application configuration and pivot to SSH as `jones`.
5. Exploit path traversal in the root-owned template-sync service to install an SSH public key for root.

## Enumeration

An initial TCP scan exposed SSH on port 22 and HTTP on port 80.

```bash
nmap -sC -sV -p- nexus.htb
```

![Nmap scan showing SSH and HTTP on Nexus](/assets/images/htb/nexus/01-nmap.png)

After mapping `nexus.htb` in `/etc/hosts`, virtual-host fuzzing identified two additional applications:

- `git.nexus.htb` — a Gitea instance.
- `billing.nexus.htb` — a Krayin CRM instance.

![Virtual-host enumeration discovering the git and billing hosts](/assets/images/htb/nexus/02-vhosts.png)

The Gitea application exposed a repository whose commit history contained an environment file. The leaked credentials provided access to the billing application.

## Initial access through the CRM

The billing host ran Krayin CRM 2.2.0. Its mail attachment feature accepted an uploaded file and returned the storage path in the response.

![Mail attachment response disclosing the stored file path](/assets/images/htb/nexus/03-upload-response.png)

The upload validation could be bypassed by submitting a PHP payload with an image extension and changing the filename back to `.php` while intercepting the request. Requesting the returned storage path executed the uploaded payload.

On the attacking host, a listener received a shell as `www-data`:

```bash
nc -lvnp 8181
script /dev/null -c /bin/bash
```

![Reverse shell received as www-data](/assets/images/htb/nexus/04-www-data-shell.png)

The CRM configuration contained database credentials. The same password had been reused by the local user `jones`, allowing an SSH pivot. The password itself is omitted here.

## Privilege escalation

Timer enumeration revealed a recurring Gitea template synchronization job:

```bash
systemctl list-timers
systemctl cat gitea-template-sync.service
```

![Systemd timers on Nexus](/assets/images/htb/nexus/05-systemd-timers.png)

The associated service ran `/etc/gitea/template-sync.py` as root.

![The root-owned Gitea template synchronization service](/assets/images/htb/nexus/06-sync-service.png)

The script used repository paths obtained from Git objects when copying files into a staging directory. Because those paths were not constrained to remain inside the staging directory, a crafted Git tree could contain traversal components and write outside the intended destination.

The exploit created a template repository containing a crafted Git object whose effective destination was `/root/.ssh/authorized_keys`. Once the periodic job synchronized the repository, the attacker's public key was written into root's SSH configuration.

![Template synchronization processing a traversal path into root's SSH directory](/assets/images/htb/nexus/07-path-traversal-sync.png)

After the synchronization completed, SSH key authentication provided a root shell. Flag values are not included in this public article.

## Lessons learned

- Git history must be treated as permanently exposed; deleting a secret in a later commit is not enough.
- File-upload controls must validate content, extension, destination, and execution policy on the server side.
- Application and operating-system credentials should never be reused.
- Privileged synchronization services must canonicalize paths and verify that every destination remains inside an approved root directory.
- Parsing an untrusted Git tree is equivalent to processing attacker-controlled filenames.
